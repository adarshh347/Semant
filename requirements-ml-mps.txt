# Apple Silicon (arm64 / MPS) sibling of requirements-ml.txt — WEIGHTS-001 Mac gate, 2026-08-01.
#
# WHY A SEPARATE FILE, not an edit to requirements-ml.txt: that file pins the cu130 index on
# purpose, and its comment says so — the pins are there to stop a future `pip install -r` from
# silently reinstalling the CPU wheel and leaving the GTX 1650 box GPU-idle. Editing it to suit a
# Mac would re-break exactly what it is defending. The two boxes get two files.
#
# THE VERSIONS ARE IDENTICAL. The only difference is the INDEX: drop
# `--extra-index-url https://download.pytorch.org/whl/cu130` and default PyPI resolves the same
# torch 2.13.0 / torchvision 0.28.0 as arm64 wheels with MPS built in. Nothing was downgraded to
# make this work, so a mark produced here and a mark produced on the CUDA box came out of the same
# model version — which is the whole point of pinning in the first place.
#
# Verified on this box (M-series, macOS 25.5, Python 3.12.13):
#     torch.backends.mps.is_available() -> True, matmul on device OK
#     torchvision.ops.nms imports (the "operator torchvision::nms does not exist" trap is absent)
#     backend suite: 1040 passed, 9 skipped
#
# Install:
#     pip install -r requirements-ml-mps.txt
